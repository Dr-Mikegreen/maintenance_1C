# 1C Database Backup

Кроссплатформенная утилита для резервного копирования информационных баз **1С:Предприятие**.

Основная задача программы — выгрузка информационных баз 1С в файлы `*.dt` с автоматическим удалением устаревших копий.

Поддерживаются:

- файловые базы 1С;
- сетевые файловые базы;
- PostgreSQL;
- Microsoft SQL Server (MSSQL).

В одной конфигурации можно использовать файловые базы и **только одну СУБД**: PostgreSQL или MSSQL.

---

# Запуск

Программа поддерживает два режима запуска.

## Однократный запуск
```text
run --now
```

В этом режиме программа выполняет резервное копирование **без учёта настроек расписания**.

Основные этапы:

1. проверка конфигурации;
2. проверка окружения;
3. подготовка окружения;
4. выгрузка информационных баз в `*.dt`;
5. запись результата в журнал.

## Запуск по расписанию
```text
run
```
В этом режиме программа определяет базы, которые необходимо обработать, согласно настройкам `schedule_settings`.
Можно добавить в планировщик и запускать каждый день. Программа сама определит по какому расписанию сработать или пропустить день.

Основные этапы:

1. проверка конфигурации;
2. проверка окружения;
3. подготовка окружения;
4. определение баз согласно расписанию;
5. удаление устаревших резервных копий;
6. выгрузка баз в `*.dt`;
7. запись результата в журнал.

Поддерживаются три типа расписаний:

- `daily` — ежедневно;
- `weekly` — еженедельно;
- `monthly` — ежемесячно.

Конкретная база указывает, в каких расписаниях она участвует, через параметр `schedules`.

Если на один день приходится несколько расписаний, используется приоритет:

```text
monthly → weekly → daily
```

Например, если день одновременно является ежемесячным и ежедневным, для этой базы выполняется только ежемесячное расписание.

# Требования

Для работы программы необходимы:

- установленная платформа **1С:Предприятие**;
- `ibcmd`;
- права на чтение и запись необходимых каталогов;
- доступ к PostgreSQL или MSSQL, если используются базы соответствующего типа;
- `cifs-utils` в Linux для работы с сетевыми файловыми базами.

Путь к `ibcmd` задаётся в конфигурации:

```yaml
general:
  ibcmd_path: "/opt/1cv8/x86_64/8.5.1.1529/"
```

> **Важно:** после обновления платформы 1С необходимо проверить и при необходимости изменить `ibcmd_path`.

# Конфигурация

Основной файл:

```text
config.yaml
```

Пример минимальной конфигурации:

```yaml
general:
  backups_path: "/home/admins/backup/"
  ibcmd_path: "/opt/1cv8/x86_64/8.5.1.1529/"
  log_path: "/home/admins/backup/log/"
  time_to_start: ""
  secrets_file: "/home/admins/go-projects/maintenance_1C/secrets.yaml"
  mount_path: "/mnt/"

server_settings:
  dbms: "PostgreSQL"
  srv: "localhost"
  port: 5433

schedule_settings:
  daily:
    schedule_backup_dir: "daily"
    schedule_days:
      - 1
      - 2
      - 3
      - 4
      - 5
    delete_older: 1

  weekly:
    schedule_backup_dir: "weekly"
    schedule_days:
      - 6
    delete_older: 1

  monthly:
    schedule_backup_dir: "monthly"
    schedule_days:
      - 15
      - 31
    delete_older: 1

bases:
  - mode: "file"
    dbdir: "//172.30.1.11/TestFileDB/"
    dbname: "filedb01"
    schedules:
      - weekly

  - mode: "file"
    dbdir: "/home/admins/testfiledb/"
    dbname: "filedb02"
    schedules:
      - weekly
      - monthly

  - mode: "dbms"
    dbname: "test01"
    schedules:
      - daily
      - weekly
      - monthly

advansed:
  ctx_timeout: 120
```

## `general`

| Параметр | Назначение |
|---|---|
| `backups_path` | Каталог для резервных копий |
| `ibcmd_path` | Каталог с `ibcmd` |
| `log_path` | Каталог журналов |
| `time_to_start` | Время запуска при работе в режиме службы. Функция в разработке |
| `secrets_file` | Путь к файлу с учётными данными |
| `mount_path` | Каталог для временного монтирования сетевых файловых баз в Linux |

---

## `server_settings`

```yaml
server_settings:
  dbms: "PostgreSQL"
  srv: "localhost"
  port: 5433
```

`dbms` может принимать значения:

```text
PostgreSQL
MSSQL
```

Если используются только файловые базы, `dbms` можно оставить пустым.

Одновременно использовать PostgreSQL и MSSQL в одной конфигурации нельзя.

# Расписание

Расписание задаётся в секции `schedule_settings`.

### `daily`

`schedule_days` содержит номера дней недели:

| Значение | День |
|---:|---|
| `0` | воскресенье |
| `1` | понедельник |
| `2` | вторник |
| `3` | среда |
| `4` | четверг |
| `5` | пятница |
| `6` | суббота |

### `weekly`

Используется для еженедельных резервных копий.

### `monthly`

`schedule_days` содержит числа месяца.

Если указанного числа нет в текущем месяце, запуск выполняется **в последний день месяца**.

Например:

```yaml
schedule_days:
  - 31
```

будет означать запуск 28/29 февраля, 30-го числа в месяцах с 30 днями и 31-го числа в остальных месяцах.

### Хранение копий

`delete_older` задаёт срок хранения резервных копий **в часах**.

```yaml
delete_older: 720
```

означает хранение копий в течение 720 часов.

Для каждого расписания можно указать собственный каталог:

```yaml
schedule_backup_dir: "daily"
```

В результате структура может выглядеть так:

```text
backup/
├── daily/
├── weekly/
└── monthly/
```

Перед созданием новых копий программа удаляет резервные копии, срок хранения которых истёк.

# Информационные базы

Каждая база описывается в секции `bases`:

```yaml
bases:
  - mode: "file"
    dbdir: "/home/admins/testfiledb/"
    dbname: "filedb01"
    schedules:
      - weekly
```

### `mode`

Тип базы:

- `file` — файловая база;
- `dbms` — база на PostgreSQL или MSSQL.

### `dbdir`

Путь к файловой базе.

Для `dbms` не используется.

### `dbname`

Имя информационной базы.

Для файловых баз используется, в частности, при формировании имени резервной копии.

### `schedules`

Список расписаний, в которых участвует база:

```yaml
schedules:
  - daily
  - weekly
```

# Сетевые файловые базы

В Linux сетевые файловые базы указываются в формате:

```yaml
dbdir: "//172.30.1.11/TestFileDB/"
```

Для работы требуется установленный пакет `cifs-utils`.

Программа использует `mount_path` для временного монтирования сетевой директории.

Локальные файловые базы указываются обычным путём:

```yaml
dbdir: "/home/admins/testfiledb/"
```

В Windows сетевые пути поддерживаются нативно:

```text
\\WINVIRT\TestFileDB
```

# Секреты

Пароли не следует хранить непосредственно в `config.yaml`.

Для учётных данных используется отдельный файл, путь к которому задаётся через:

```yaml
general:
  secrets_file: "/home/admins/go-projects/maintenance_1C/secrets.yaml"
```

Пример:

```yaml
net:
  net_user: "TestUser"
  net_password: "123456"

dbms:
  dbms_user: "postgres"
  dbms_password: "159357"

bases:
  filedb01:
    user: ""
    password: ""

  filedb02:
    user: ""
    password: ""

  test01:
    user: ""
    password: ""
```

Если в информационной базе пользователи не созданы, соответствующую запись в `bases` можно не добавлять.

## Защита файла с паролями

Файл `secrets.yaml` не должен быть доступен другим пользователям системы.

В Linux рекомендуется:

```bash
chmod 600 secrets.yaml
```

Файл также следует добавить в `.gitignore`:

```gitignore
secrets.yaml
```

В Windows доступ к файлу следует ограничить с помощью NTFS ACL.

# Дополнительные настройки

```yaml
advansed:
  ctx_timeout: 120
```

`ctx_timeout` — максимальное время выполнения выгрузки базы в минутах.

После истечения указанного времени операция прерывается.

# Статус проекта

Проект находится в разработке.

Формат конфигурации и набор возможностей могут изменяться между версиями.


## Планируемые функции

- Остановка и запуск службы сервера 1С перед выполнением операций резервного копирования.

- Проверка выгруженных резервных копий:
  - первичная проверка на нулевой размер файла;
  - проверка путем загрузки копии в тестовую информационную базу с последующим удалением тестовой базы.

- Отправка уведомлений о результатах работы программы на почту и/или в мессенджер.

- Обслуживание баз средствами СУБД:
  - **PostgreSQL:** `ANALYZE`, `REINDEX`, `VACUUM`, `VACUUM FULL`;
  - **MSSQL:** `STATISTICS` (`UPDATE STATISTICS`), `INDEXES` (`REORGANIZE` / `REBUILD`), `INTEGRITY` (`DBCC CHECKDB`).

- Запуск программы в качестве службы:
  - **Linux:** `systemd`;
  - **Windows:** Windows Service.
